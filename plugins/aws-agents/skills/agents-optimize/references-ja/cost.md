# コストの最適化

AgentCore のコストを左右するものと、それを抑える方法を理解します。料金の値は変動しやすいので、必ず [AgentCore の料金ページ](https://aws.amazon.com/bedrock/agentcore/pricing/)で確認してください。

## コストの構成要素

AgentCore は、いくつかの項目に対して個別に課金します。

| 構成要素 | 課金の対象 | 公開されている料金(最新は要確認) | コストの最大の要因 |
|---|---|---|---|
| **Runtime のコンピューティング** | セッションがアクティブな間の vCPU 時間 + GB 時間 | $0.0895/vCPU 時間、$0.00945/GB 時間 | セッションの長さ、アイドルタイムアウト、コールドスタート |
| **Memory のイベント** | イベントの作成(書き込み) | 新規イベント 1,000 件あたり $0.25 | セッション数、戦略の数 |
| **Memory のストレージ** | 保存された長期 Memory のレコード | 1,000 レコードあたり月 $0.75(組み込み)、$0.25(オーバーライド/セルフマネージド) | 戦略の数、有効期限 |
| **Memory の取得** | Memory レコードの取得 | 1,000 回の取得あたり $0.50 | 取得の頻度、top_k の値 |
| **Gateway のツール呼び出し** | Gateway 経由でルーティングされる、ツール呼び出しごと | 1,000 回あたり $0.005(ListTools/InvokeTool/Ping)、1,000 回あたり $0.025(Search) | ツール呼び出しの量 |
| **評価器のモデル呼び出し** | LLM-as-judge の評価器による Bedrock のモデル使用量 | 組み込み: 入力 1 万トークンあたり $0.0024、出力 1 万トークンあたり $0.012、カスタム: 1 万回の評価あたり $1.50 | オンライン評価のサンプリングレート × セッション数 |
| **Bedrock のモデル使用量** | すべてのモデル呼び出しの入力/出力トークン | モデルによって異なる — Bedrock の料金を確認 | モデルの選択(Sonnet か Haiku か)、会話の長さ |
| **ポリシーの認可** | 認可リクエストごと + 入力トークン | リクエストあたり $0.000025、入力 1 万トークンあたり $0.13 | ポリシーエンジンがアタッチされている場合のツール呼び出しの量 |
| **Identity** | AWS 以外のリソースに対する、トークン/API キーのリクエスト | 1,000 リクエストあたり $0.010 | 認証情報の取得頻度 |
| **CloudWatch のログ/トレース** | 取り込みと保存 | CloudWatch の標準料金 | ログの詳細度、保持ポリシー |
| **ECR のストレージ**(Container ビルドのみ) | イメージの保存 | ECR の標準料金 | イメージのサイズ、ビルドの頻度 |

上記の料金は、執筆時点で公開されているものです。料金はリリースごとに変わるため、必ず [AgentCore の料金ページ](https://aws.amazon.com/bedrock/agentcore/pricing/)で確認してください。

## 初日によくあるコストの質問

### 「1 回の呼び出しあたり、エージェントのコストはいくらになりますか?」

1 つの数字では答えられません。次の要素に依存します。

- どのモデルか(Haiku は、トークンあたり Sonnet の約 10 分の 1 の価格です)
- セッションがどれだけアクティブな状態を保つか(Runtime はリクエストごとではなく、vCPU 時間と GB 時間で課金されます — アイドル状態のセッションにもお金がかかります)
- ツールを使うか(Gateway の呼び出しは 1,000 回あたり $0.005 に加えて、Lambda や API のコストがかかります)
- Memory の抽出が実行されているか(非同期で、別途 1,000 イベントあたり $0.25 で課金されます)
- 会話がどれだけ続くか(トークンが増えるとモデルのコストが増え、アクティブなセッションが長くなるとコンピューティングのコストが増えます)

Memory もツールもない、Haiku ベースのシンプルなエージェントは、リクエストあたりのコストがごくわずかです。Runtime のコンピューティングは、vCPU 時間($0.0895)と GB 時間($0.00945)で課金されるため、小さな環境での 1 秒未満のリクエストは、1 セントの数分の 1 のコストで済みます。セマンティック Memory、5 つの Gateway ツール、10% サンプリングのオンライン評価を備えた Sonnet のエージェントは、リクエストあたりのコストがはるかに高くなります。モデルのトークンコストだけで 10〜30 倍になることがあり、そこに Memory の抽出(1,000 イベントあたり $0.25)、Gateway のツール呼び出し(1,000 回あたり $0.005)、評価のモデル使用量が加わります。これらは執筆時点の公開料金です。最新の数字は、[AgentCore の料金ページ](https://aws.amazon.com/bedrock/agentcore/pricing/)で確認してください。`awsknowledge` MCP サーバーが利用できる場合は、`aws___search_documentation` ツールで最新の AgentCore の料金を調べられます。

### 「このデモ/プロトタイプには、いくらかかりますか?」

開発中は、`--defaults` のフラグ(Strands、Bedrock、Memory なし)を使います。可能な限り、無料枠の範囲に収めてください。最も予想外になりやすいのは、次の点です。

- **アイドル状態のセッションがコンピューティングを消費する** — Runtime は、セッションがアクティブな間、`idleRuntimeSessionTimeout` で回収されるまでのアイドル時間を含めて、vCPU 時間で課金します。デフォルトのタイムアウトは 15 分です。終わったら `StopRuntimeSession` を呼び出すか、タイムアウトを短くしてください。`agents-harden` の「Session lifecycle management」を参照してください。
- オンライン評価の設定を、100% のサンプリングで動かしたままにする
- CloudWatch のログの保持期間を設定し忘れる(デフォルトは無期限)
- 高価な戦略(SEMANTIC や EPISODIC)を使ったテスト用の Memory リソースを残しておく

## コスト削減のレバー

### モデルの選択

AgentCore は 4 つのモデルプロバイダーをサポートしています。デフォルトだけでなく、タスクに合ったものを選んでください。

| モデルの階層 | 例 | 適している用途 |
|---|---|---|
| **最も安価 / 最も単純** | `amazon.nova-micro-v1:0`、`claude-3-5-haiku-*`、Gemini Flash、GPT-5-nano | 分類、抽出、単純なルーティング、短い応答 |
| **中位** | `amazon.nova-lite-v1:0`、Gemini 2.5 Flash | 軽い推論を伴う、ほとんどの汎用エージェント |
| **高価格帯 / 推論** | `anthropic.claude-sonnet-4-5-*`、GPT-5、Gemini 2.5 Pro | 複雑な推論、コード生成、複数ステップの計画 |

経験則:

- 単純な抽出タスクには、Haiku または Nova Micro(トークンあたり、Sonnet の 10〜30 分の 1 の価格)
- Sonnet/Opus/GPT-5 は、推論を多用するワークフローのために取っておく
- **エージェントと評価器で、別のモデルを使う** — Sonnet のエージェントを Haiku ベースの評価器で採点するのは、コスト効率の良い一般的なパターンです
- コストを重視するカスタマーサポートや分類のエージェントは、Nova Lite や Gemini Flash から始めて、品質が不十分な場合にのみアップグレードする

### Memory

- 実際に使う戦略だけを有効にする — 長期 Memory の戦略は、セッションごとに抽出を実行します
- `SEMANTIC` は最も高価な戦略です。セッションの要約だけが必要なら、`SUMMARIZATION` だけを使います。
- `relevance_score` を上げて、クエリごとに取得される Memory レコードを減らす
- `--expiry` は、ユースケースに合う最短の期間に設定する(デフォルトは 30 日)

### オンライン評価

- 本番では、100% ではなく、1〜5% のサンプリングから始める
- デバッグや試行錯誤の間は、`agentcore pause online-eval <name>` を使う — 測定する準備ができたら再開する
- シグナルが得られる最小限の評価器のセットを選ぶ

### ログとトレース

- ロググループに保持ポリシーを設定する:

  ```bash
  aws logs put-retention-policy \
    --log-group-name /aws/bedrock-agentcore/runtimes/<AGENT_ID>-DEFAULT \
    --retention-in-days 30
  ```

- ペイロード全体をログに出さない — 必要なものだけを含む、構造化されたイベントをログに出す
- X-Ray のサンプリングは自動で設定される。調整するダイヤルはない

### Gateway

- ツール呼び出しは、バイト数ではなく、呼び出し回数で課金される。重要なのは量であって、ペイロードのサイズではない。
- 同じ静的なデータのために、呼び出しのたびにツールを呼んでいる場合は、そのデータをシステムプロンプトに組み込むことを検討する

### Container ビルド

- Container が不要なら、CodeZip を使う — ECR のストレージ料金がかからない
- Container が必要なら、イメージを小さく保つ(`agents-harden` の「Initialization time」セクションを参照)
